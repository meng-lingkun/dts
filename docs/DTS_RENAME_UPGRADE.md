# DTS 更名与升级

项目展示名称统一为 DTS，环境变量前缀为 `DTS_`，Go 模块为 `dts/backend`，命令行入口为 `dtsctl`，运行程序及镜像前缀为 `dts`。脚本、原生 Provider 接口、监控指标、前端存储键及部署清单已同步更新。

这是包含配置及接口名称变化的版本，现有部署不能只替换镜像后继续使用旧配置：

- 将自定义环境变量改为 `DTS_` 前缀，并重新构建镜像、CLI 和原生 Provider 插件。外部调用方需同步更新命令名、C 接口符号、请求头和监控指标引用。
- Kubernetes 默认命名空间为 `dts`。安装到此命名空间会创建独立资源，不会自动迁移旧命名空间的数据、PVC 或 Secret。
- 升级前备份元数据库、共享 CDC 数据和原有 Secret；恢复时保留原来的加密主密钥、数据库凭据等必要配置，否则旧的加密数据源凭据无法解密。应在停写、停止迁移任务后按客户存储方案恢复并验收。
- 浏览器存储键更名后需要重新登录。
- 仓库 dist 中已有压缩包、镜像及二进制属于旧构建产物；必须重新构建 DTS 离线包后交付，不能通过修改压缩包文件名完成升级。

先在测试环境验证连接测试、全量/CDC 迁移、暂停恢复以及回切，再切换生产部署。
