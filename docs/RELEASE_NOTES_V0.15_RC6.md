# QMigration V0.15.0-rc6 Release Notes

## Release purpose

RC6 closes the remaining DB2 Full Migration target-LOB gap left by RC5. DB2
LUW remains `EXPERIMENTAL` pending retained real-instance qualification, and
DB2 source CDC is still intentionally not advertised.

## DB2 Prepared target data plane

- DB2 Full Writer / target CDC Apply no longer embeds row values into SQL text.
- QMigration prepares a stable INSERT/MERGE statement and executes each row via
  DRDA `EXCSQLSTT + SQLDTA`.
- SQLDTA contains native FDODSC/FDODTA parameter descriptors/data for integer,
  exact DECIMAL, float, boolean, date/time/timestamp, character and binary
  families.
- Target parameter markers are explicitly CAST to the compiled DB2 target type
  to avoid ambiguous/untyped parameter markers in heterogeneous migrations.
- Multiple rows share one prepare operation and are pipelined in one DRDA
  request chain per QMigration WriteBatch.

## BLOB/CLOB EXTDTA

- BLOB/CLOB values over 32 KiB are carried out-of-line in DRDA EXTDTA objects.
- SQL text contains parameter markers only; large LOB bytes never appear in
  generated SQL.
- DSS framing is now generic for extended DDM objects and supports an arbitrary
  number of continuation segments, not just the old single QRYDTA continuation.
- The same reassembly hardening also covers large source-side EXTDTA responses.
- Logical DRDA objects are bounded to 256 MiB to prevent a worker from accepting
  unbounded request/response allocations.

## Numeric correctness

- DECIMAL/NUMERIC parameters are converted to DB2 packed-decimal bytes without
  float64 conversion.
- Scientific notation is expanded exactly.
- Values that exceed target precision or would require rounding to the target
  scale fail closed before network execution.

## DB2 LUW identity lifecycle correction

RC6 corrects the identity write strategy for Db2 LUW. Normal LUW INSERT does not
accept an explicit value for a `GENERATED ALWAYS` identity, so QMigration now
creates that target identity as migration-stage `GENERATED BY DEFAULT` while Full
Load and target CDC propagate exact source values. `START WITH` / `INCREMENT BY`
metadata is retained and `RESTART WITH` keeps the next generated value aligned.
For Full-only tasks the source `ALWAYS` mode is restored immediately before
FINISHED. For Full+CDC, managed native capture is stopped, the final durable spool
is drained, generator state is synchronized again, and only then does the cutover
critical section execute `ALTER COLUMN ... SET GENERATED ALWAYS`.

## Qualification

`qmigration-db2-qualify --target-write` now forces the RC6 path with a 2 MiB
BLOB and a large UTF-8 CLOB and verifies byte-for-byte readback. Identity,
rollback, CDC-target transaction, point lookup and index checks remain included.

## Explicit boundary

DB2 source CDC is not implemented or advertised. RC6 does not silently switch
to IIDR, Q Replication, JDBC polling or another external migration runtime.
